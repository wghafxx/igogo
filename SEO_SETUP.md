# BloxGrade: запуск индексации

После публикации изменений на Railway нужно отдельно добавить TXT-запись Google в DNS и подтвердить права в аккаунтах поисковых систем. Git-деплой не выполняет эти действия автоматически.

## Что обнаружено 25 сентября 2026 года

- Главная bloxgrade.com отвечает HTTP 200.
- Вместо robots.txt, sitemap.xml и файла Яндекса сервер возвращает HTML приложения. Эти файлы отсутствовали в public.
- Авторитетные DNS-серверы: ns1kpv.name.com, ns2cvx.name.com, ns3gnv.name.com, ns4fpy.name.com. Хостинг сайта — Railway, по информации владельца.
- В полученном ответе DNS есть SPF-запись; TXT подтверждения Google отсутствует.

## Google: добавить DNS-запись

В панели, управляющей DNS домена (текущие серверы принадлежат Name.com), открыть bloxgrade.com → Manage DNS Records и добавить отдельную запись:

| Поле | Значение |
| --- | --- |
| Type | TXT |
| Host | Пустое поле для корневого домена в Name.com |
| Answer / Value | `google-site-verification=LejXBGd9eF5-r_Y60M8DnV3hErKYOSoPmv6N9n9IZsI` |
| TTL | 300 |

Строка записывается без обратного слеша перед `_`, без кавычек и переносов. Существующую SPF-запись, A/CNAME и NS сохраняем: добавляется новая TXT-запись.

После распространения DNS нажать «Подтвердить» в Google Search Console. Если запись ещё не обнаружена, повторить позже. TXT-запись оставить после подтверждения. Для выбранного доменного ресурса HTML-файл или метатег не заменяют DNS-подтверждение.

Инструкции: [Name.com](https://www.name.com/support/articles/115004972547-adding-a-txt-record), [Google Search Console](https://support.google.com/webmasters/answer/9008080?hl=ru).

## Railway и Яндекс

1. Проверить в Railway у сервиса сайта Settings → Source, какой GitHub-репозиторий и ветка используются. Локальная рабочая ветка: `codex/latest-20260925`.
2. Опубликовать проверенные изменения в подключённой ветке. При включённом GitHub Autodeploy Railway запустит сборку автоматически; дождаться успешного deployment.
3. Проверить https://bloxgrade.com/yandex_42e63b05a5e48470.html — страница должна показывать `Verification: 42e63b05a5e48470`, а не интерфейс сайта.
4. Проверить https://bloxgrade.com/robots.txt — обычный текст, и https://bloxgrade.com/sitemap.xml — XML с шестью публичными адресами.
5. Нажать «Подтвердить» в Яндекс Вебмастере. Файл подтверждения оставить в проекте.
6. В Google Search Console → Sitemaps и Яндекс Вебмастер → Индексирование → Файлы Sitemap добавить `https://bloxgrade.com/sitemap.xml`.
7. В Google → Проверка URL проверить `https://bloxgrade.com/ru` и запросить индексирование. В Яндексе отправить этот адрес на переобход. Аналогично проверить `/en`.

Инструкции: [Railway Autodeploy](https://docs.railway.com/deployments/github-autodeploys), [Яндекс: подтверждение](https://yandex.ru/support/webmaster/ru/service/rights), [Яндекс: Sitemap](https://yandex.ru/support/webmaster/ru/indexing-options/sitemap).

## Что улучшено в коде

- Точная копия файла Яндекса размещена в `frontend/public` и попадёт в сборку.
- robots.txt разрешает обход страниц и ресурсов интерфейса, ограничивает `/api/` и указывает карту сайта.
- Sitemap содержит `/ru`, `/en` и переводы соглашения и политики конфиденциальности. Личные кабинеты, профили пользователей и админка не включены.
- Метаданные меняются при переходах: заголовок, описание, canonical без рекламных параметров, языковые альтернативы ru/en, Open Graph и Twitter.
- Служебные страницы и неизвестные адреса получают `noindex` после выполнения JavaScript. Это указание поисковику, а не механизм ограничения доступа.
- На главной добавлено короткое видимое описание сервиса. Изображения для предпросмотра используют адрес основного домена вместо адреса API.

## Следующие шаги для роста поиска

Подтверждение прав и Sitemap помогают поисковикам обнаружить сайт; они не гарантируют индексацию или первое место.

1. Сначала проверить появление по брендовым запросам «BloxGrade», «блоксгрейд». Затем оценивать запросы «апгрейд скинов BloxStrike» по фактическим показам и кликам в Search Console.
2. Подготовить полезные самостоятельные страницы: как работает апгрейд и его вероятность; как пополнить баланс; как получить предмет; как обратиться в поддержку. Только достоверные инструкции по текущему интерфейсу, без обещаний гарантированного выигрыша. Каждой странице нужны собственный адрес, заголовок и ссылки из интерфейса.
3. Следующий технический этап — серверный рендеринг или предварительная генерация публичных страниц. Сейчас основной контент и метаданные маршрутов зависят от JavaScript. Проверить отрисованную страницу в инструментах поисковиков; также доработать настоящие HTTP 404 для отсутствующих страниц.
4. Проверить мобильную скорость загрузки через PageSpeed Insights и устранить реальные узкие места по результатам измерений.
5. Добавить ссылку на сайт в собственные публичные сообщества. Раз в неделю смотреть индексацию, ошибки, запросы, показы и переходы. Оценивать эффект SEO в течение недель и месяцев, без обещания конкретной позиции.

Основа: [Google SEO Starter Guide](https://developers.google.com/search/docs/fundamentals/seo-starter-guide), [JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).
