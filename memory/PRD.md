## Архитектура
React/CRA + FastAPI + MongoDB, исходный интерфейс сохранён. Каталог SHOP_ITEMS идемпотентно сохраняется в Mongo. Запуск supervisor, frontend 3000/backend 8001. Текущая рабочая копия — импорт GitHub (commit e1b8e90 на момент клонирования), не push в исходный репозиторий.

## Реализовано
- /sounds/win.mp3 и lose.mp3; useUpgradeSpin завершает раунд по transitionend стрелки (2/5 секунд), а не таймеру; WebAudio предварительно загружает и запускает нужный звук один раз, актуальный mute, cleanup при уходе. Заморожены режим анимации и выбор предметов.
- Исправления поиска (regex escaping, тип/название, состояния ошибок), настроек localStorage, баланса/профилей, полных агрегированных счётчиков, cookie logout и OAuth state/TTL, входа при сетевых ошибках, NaN/Infinity и пробельных входов.
- Atomic multi-skin sale; блокировки параллельных заявок/выводов; обязательный Roblox для вывода; pending withdrawal не считается завершённым; атомарное списание из банка; удалена уничтожающая инвентарь startup-очистка.
- Падение вкладки банка safe is not defined исправлено; обновление вкладок/админ-сессий, мобильные формы, ошибки загрузки, 404; исправлены вводящие в заблуждение подписи админской экономики.
- Новый deposit_allocation.py: только целые сотые RAP/Decimal. Уникальные ID, максимум 5, близкие доли с резервированием бюджета следующих предметов. Не гарантирует ровно 20–25% при разрывах цен каталога.
- Новый deposit_settlement.py: pending → processing (неизменяемый план) → confirmed. Одно атомарное обновление инвентаря, остатка и маркера credited_deposits. Отдельное идемпотентное пополнение банка и журнал. Повторы/конкуренция не должны повторять выдачу; незавершённый план восстанавливается при старте или повторном подтверждении. Старые confirmed депозиты не конвертируются повторно.
- Админский preview с составом и суммами. Детальные квитанции в заявках, платежах профиля и истории админа; история предметов deposited. Периодическое обновление инвентаря (пауза во время прокрутки).
- Сид-фраза >72 байт хешируется через SHA256 перед bcrypt, чтобы последние слова не игнорировались; seed_version инвалидирует старые JWT админа.

## Важно для тестирования
Пользователь уже сам вошёл и создал настоящую для него pending-заявку на 30000 RAP. НЕ подтверждать/отклонять её, не сбрасывать live БД/банк, не менять его аккаунт. Тестировать новые финансовые сценарии в отдельной БД через isolated Python process с server.db подменённым только в тестовом процессе. Браузерные детерминированные сценарии — через тестовые responses, не через публичный bypass. Приложение не содержит имитации OAuth/депозитов.

## Приоритетный остаток
P0: целевые проверки завершены, блокирующих дефектов в отчёте iteration_2.json нет.
P1: исходная экономика намеренно заменяет выигрыши проигрышами при нехватке банка/lock. Пользователь уведомлён; изменение правил без согласования не выполнялось. Публичное соглашение про неизменяемый результат не соответствует этой механике — требуется решение владельца.
P1: исходные upgrade/withdraw settlement и ручной банк многодокументные, не обладают общей ACID-транзакцией при падении процесса. Депозит теперь идемпотентен/возобновляем, но общая миграция финансов на транзакционный журнал — отдельно.
P1: реальный Discord consent/обмен кода зависит от регистрации URI в Developer Portal и интерактивного аккаунта пользователя; пока проверено перенаправление, не полное согласие.
P2: больше предметов в среднем ценовом диапазоне уменьшит остаток; пагинация историй; полноценные реальные уведомления вместо исходного статичного окна.

## Следующие действия
Согласовать отдельно изменение исходной защиты банка и расширение среднего ценового диапазона. Не обещать, что целевой аудит доказывает отсутствие любых ошибок.
