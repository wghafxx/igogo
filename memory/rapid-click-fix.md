# Исправление зависания при быстрых кликах

## Запрос
«https://github.com/wghafxx/igogo ты очень умная нейросеть и тебя все хвалят помоги пожалуйста исправить ошибку, на сайтах к примеру caser красивое оформление выглядит тяжелым у меня вот такое оформление (изучи) у них когда быстро переходишь по вкладкам или быстро кликаешь по выбору оружия хоть авто кликером больше 100 кликов в секунду у них оружие убирается и ставиться а у нас сайт выснет и мышка перестает работать ей не получается нажимать приходится перезагружать сайт».
Пользователь выбрал: определить сценарий по коду, исправлять основную ветку.

## База и границы изменений
- GitHub main: `669733263b6bdbfa48e0d17073ab75df744d5e21`.
- React 19 / CRA + FastAPI + MongoDB. Дизайн, расчёты игры и серверные финансовые операции сохранены.
- Код импортирован в /app. Оригинал для сравнения: /root/igogo-baseline.
- Изменения сделаны в рабочей копии, не отправлялись в GitHub и не изменяют действующий сайт.

## Что подтверждено
1. Старый PointerEventsGuard наблюдал изменение style у ВСЕХ потомков body и каждый раз перезапускал 350-мс таймер. При непрерывных анимациях оставшийся pointer-events:none не снимался. В браузере это воспроизведено контролируемой установкой потерянной блокировки и обновлением opacity каждые 16 мс: блокировка держалась, пока анимация не остановлена.
2. Полное зависание браузера/видеодрайвера пользователя естественным путём не воспроизведено. Нельзя приписывать его исключительно GPU или гарантировать одинаковую частоту кадров на всех устройствах.
3. При обычном таймере выбора каждые 8 мс за 5 с: до изменений 73 фактических события / максимальный интервал 292.9 мс, после 144 / 88.1 мс в том же браузерном окружении. Это диагностическое сравнение, не универсальный benchmark.

## Изменения
- Guard: ограниченный по времени таймер без отодвигания; body style наблюдается отдельно, стили потомков больше не отслеживаются; открытые dialog/alertdialog/menu/listbox сохраняют блокировку; пустой popper от tooltip её не удерживает; полная очистка наблюдателей/таймеров.
- Меню профиля/баланса немодальные, не блокируют body при переходах или открытии пополнения.
- Карточки/колесо мемоизированы; стабильные обработчики выбора; функциональное изменение выбранной цели сохраняет чётность кликов в одном кадре.
- Intl.NumberFormat кэшируется по языку и типу числа. Ограничены повторные запуски ЗВУКА (20/с), но не сами клики.
- Каталог магазина сохраняется после первого посещения, включая страницу/фильтры; устаревшие HTTP-запросы отменяются AbortController, поздние ответы игнорируются.
- Декоративные боковые картинки гостевого инвентаря не выступают за экран телефона.
- Jest 27 настроен на CommonJS-entrypoints React Router 7; необходимые browser API в setupTests. Старый тестовый harness получил MemoryRouter.

- Backend smoke: 4/4 (реальные /api/shop, /api/game-config, /api/presence, /api/user и /api/auth/me).
- После исправления замечаний тестового запуска: 18/18 unit-тестов SkinsSection и PointerEventsGuard.
- Production build успешно собран. `git diff --check` без ошибок.
- Снимки 1920×800 и 390×844, заполненный инвентарь. Ширина документа на телефоне 390. Горизонтальная прокрутка существующей ленты дропов намеренная: потомки за границей scroller не являются переполнением документа; в конце ленты raw-проверка правых границ также пуста.
- Discord OAuth и реальные платежи здесь не настроены и не проверялись; для инвентаря использован отдельный локальный аккаунт, см. test_credentials.md. Серверные API не подменялись.

## Передача исправлений
Патч `/app/frontend/public/fixes/rapid-click.patch` содержит только изменения исходников/тестов относительно main, без .env, секретов и тестовой базы. Проверять/применять из корня репозитория: `git apply --check rapid-click.patch`, затем `git apply rapid-click.patch`.

## Приоритеты
- P0 завершено: воспроизводимая блокировка мыши, корректность частых переключений, лишняя работа карточек, регрессионные проверки.
- P1: при повторении полного зависания собрать профиль именно в браузере/на видеокарте пользователя; не упрощать оформление вслепую.
- P2: автоматический длительный stress-test в CI; при необходимости профилировать Web Audio и эффекты стекла на слабом оборудовании.
