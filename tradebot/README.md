# Roblox Trade Plaza — приёмщик трейдов

Windows-программа на Python: находит входящие запросы, сверяет **точный username**, открывает разрешённый трейд, проверяет предметы и отправляет **один ACCEPT** после стабилизации предложения. Это управление открытой игрой, не веб-сайт. Зачислений на сайте нет.

## Обновление: клики и оба имени

Если уже есть калибровка прошлой версии, сохрани свой `config.yaml` и папку `templates`. Замени Python-файлы из обновлённого архива (включая новый `identity.py`) и выполни:

```powershell
python calibrate.py --names-only
python bot.py --check
python bot.py
```

Короткое обновление попросит выделить **четыре области**: постоянный заголовок списка `Select Player To Accept Or Decline Trades`, верхнее имя первой строки, нижний `@username` той же строки, имя партнёра внутри трейда. Координаты кнопок, сеток и правила сохраняются. Esc отменяет обновление без изменения старых файлов. Если вообще нет калибровки — используй обычный `python calibrate.py`.

**Как сверяются имена:** в списке, например, сверху `Cool Panda`, снизу `@ysrent3`. Разрешение определяется **только по `ysrent3` в `only_nicks`**. Из этой же строки запоминается `Cool Panda`. Перед нажатием повторно сверяются обе строки. В открывшемся трейде бот ожидает сохранённое `Cool Panda`, поскольку там нет `@username`. Верхнее имя само по себе никогда не добавляет игрока в разрешённые: у разных пользователей оно может совпадать. Связь строится из проверенного запроса и наблюдаемого перехода в трейд, но не является независимым доказательством уникального аккаунта внутри окна обмена.

**Как обрабатывается очередь:** человечек → первая строка → чтение обоих имён → чужой username отклонить → дождаться смены строки → снова первая строка. Ограничения в 12 строк нет. Разрешённый запрос открывается и проходит проверки предложения; после завершения бот возвращается к очереди. CLOSE нажимается только после трёх подтверждений пустоты. Ошибка OCR/подсветка/временно отсутствующая кнопка не закрывает список: выполняется повтор с паузой. Нечитаемый запрос не отклоняется вслепую; пока он не прочитается или не исчезнет, дальнейшая очередь может ожидать.

Распознавание кнопок допускает изменение яркости и небольшой масштаб при наведении, но сохраняет проверки формы, цвета, координат и состояния. Серый/красный ACCEPT не заменяет активный зелёный. В журнале различаются `Клик отправлен: ...` и конкретная причина `Без нажатия: person: ...`. При отмене сохраняются `debug/click-before.png`, при наличии — `click-after.png`, и `click-reason.json` (не чаще раза в 5 секунд).

Опрос рассчитан на длительную работу; **это не гарантия бесперебойной работы 24/7**. Потеря фокуса, смена размера, неизвестный итог финального ACCEPT по-прежнему останавливают ввод. Тесты без Windows не доказывают доставку ввода драйвером в Roblox.

## Быстрый запуск

Нужны Windows 10/11, Python 3.11+, Tesseract OCR с English и открытый Roblox. Для выбранного по умолчанию `interception` требуется установленный драйвер Interception и перезагрузка ПК. Программа не обходит ограничения игры и не гарантирует, что Roblox примет синтетический ввод.

В терминале из папки проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item config.example.yaml config.yaml
.\.venv\Scripts\python.exe calibrate.py
```

**Не перезаписывай существующий `config.yaml` командой Copy-Item.** Далее используй Python из `.venv`; команды ниже сокращены до `python`.

1. Калибруй четыре состояния: обычный экран → список запросов → трейд → уведомление успеха. При переходе программа сама возвращает фокус выбранному Roblox. Не меняй аккаунт/размер игры.
2. В `config.yaml` заполни `only_nicks: [YourActualUsername]` — настоящий Roblox username, не Display Name. Пустой список запрещает запуск.
3. Если Tesseract не в PATH, задай `tesseract_cmd: 'C:\Program Files\Tesseract-OCR\tesseract.exe'`.
4. Выполни `python bot.py --check` — настройки, шаблоны, OCR и окно, без движения мыши/кликов.
5. Открой тестовый трейд: `python bot.py --dry-run --expected-username ysrent3 --expected-display-name "Cool Panda"` — проверка предложения без ввода. Подставь оба имени из реального исходного запроса. Без них команда покажет, что связка не подтверждена, а не угадает username по отображаемому имени.
6. Закрой трейд и запусти `python bot.py`.

**Остановка: F8 или Ctrl+C.** Не пользуйся мышью/другими окнами во время работы. F8 проверяется во время движения и пауз, до и после каждого OCR; отдельный вызов OCR ограничен 2 секундами. Нажатая кнопка отпускается даже при исключении.

## Правила и защита

- Принимаются только точные usernames из списка (регистр не важен). Никаких «похожих» ников и подмен `0/o`, `1/l`.
- Чужие читаемые запросы отклоняются; нечитаемый ник пропускается без клика и проверяется при следующем просмотре списка.
- Наш Total RAP должен быть **0**, каждый из 9 наших слотов — подтверждённо пустым.
- RAP каждого их предмета сверяется с `whitelist_rap`, количество с `max_items`, сумма с `min_total_rap` и Total RAP.
- При `single_page_only: true` допускается только читаемое **1/1**. Ни пустая надпись, ни `11` не подходят.
- До ACCEPT стабилизируются сохранённая связка имён, обе суммы, пагинация, значения всех слотов и изображение предметов, а не только общая сумма.
- Перед нажатием — повторное распознавание и ещё один снимок после OCR. Изменение предметов во время чтения отменяет клик.
- Захват — только клиентская область **конкретного процесса Roblox**, не весь монитор. Чужое окно с заголовком Roblox не подходит.
- Потеря фокуса, перекрытие цели, изменение окна во время клика или недостижение точки мышью отменяют ввод. Размер должен совпадать с калибровкой.
- После ACCEPT успех требует нового уведомления успеха и устойчивого возврата из трейда. Одно исчезновение окна не означает успех. Учитываются задержанные уведомления.
- Неизвестное завершение останавливает работу. `config.state.json` сохраняет намерение ACCEPT до ввода и запрещает повтор после перезапуска.
- Одновременно может работать только один бот/калибровщик в сеансе Windows.

RAP-фильтр **не доказывает идентичность предмета**: разные предметы могут иметь одинаковую оценку. Проверка изображения обнаруживает изменения между наблюдениями, но не заменяет каталог предметов. OCR и экранная автоматизация не дают абсолютной гарантии; сначала используй малозначимые тестовые предметы. На нескольких страницах невидимые предметы не проверяются — оставляй `single_page_only: true`.

## Калибровка без потери прошлых настроек

Присланная новая логика встроена в `calibrate.py`, `bot.py`, `offer.py` и дополнена совместимыми `desktop.py`, `configuration.py`, `vision.py`, `mouse.py`.

- Координаты первой версии отвергаются: нужна новая калибровка. Для версии 2 достаточно `--names-only`; актуальная версия — 3.
- Esc при обязательной области отменяет **всю** новую сессию. Для необязательного бейджа — пропуск. В диалоге выделения используй Esc, не F8.
- Новые PNG пишутся в отдельную `templates/calibration-…`. Старые шаблоны не перезаписываются.
- Перед сохранением проверяется полнота/качество шаблонов и областей. YAML заменяется атомарно; предыдущий сохраняется как `config.yaml.bak`.
- Обводи кнопки вместе с текстом/контуром, не однотонную заливку. Для цифр — **только полное число**, для username — только `@username`.
- `trade_anchor` — постоянный заголовок/значок, не меняющаяся ACCEPT.
- Уведомление успеха необязательно для калибровки, но **без него автоматическое продолжение после ACCEPT невозможно**.
- При смене разрешения, масштаба UI/DPI, оформления или размеров Roblox повтори калибровку. Простое перемещение окна между действиями не меняет клиентские координаты.

## Диагностика

```powershell
python debug_vision.py
python test_mouse2.py
python test_mouse2.py --move-only
python test_mouse2.py --click
```

Первые две команды не двигают мышь и не кликают (могут вывести игру на передний план). Диагностика зрения пишет `debug/annotated.png`, вырезки и `debug/report.json` с найденными кнопками и прочитанными значениями. Если шаблон не найден, сначала проверь вырезку и цвет активной кнопки — не снижай пороги вслепую.

`--move-only` явно включает наведение на найденную иконку списка, `--click` — один проверенный клик по ней. Произвольных координат и слепых кликов нет. Тест требует закрытого трейда и списка. Если курсор не доходит до точки, проверь драйвер и `mouse_device` (индексы 10–19).

Interception использует основной монитор: помести на него **и игру, и курсор**. Если выбран другой монитор, доступен Windows SendInput с виртуальными координатами: `mouse_backend: sendinput` и `allow_sendinput: true`. Этот способ может игнорироваться игрой. Автоматического переключения между способами ввода нет.

Офлайн-диагностика уже снятой игровой области (поддерживает Linux):

```powershell
python debug_vision.py --image client.png --config config.yaml --output debug-offline
```

Любая команда поддерживает `--config путь`. Шаблоны и журнал разрешаются относительно файла конфигурации, не текущей папки терминала. Снимки и лог могут содержать usernames; не публикуй их без необходимости.

### После неизвестного результата

Если бот остановился после ACCEPT, **сначала проверь результат в игре вручную** и закрой трейд. Затем:

```powershell
python bot.py --resolve-pending
python bot.py
```

Сброс разрешается только после устойчивого обнаружения экрана вне трейда. Он отмечает ручную проверку, **не записывает автоматический успех**. Используй тот же `--config`. Повреждённый журнал требует ручного разбора и не сбрасывается молча.

## Проверки разработки

На Windows установи зависимости и `pytest`, затем `python -m pytest tests -q`. Linux-проверки требуют `opencv-python numpy pyyaml mss pytesseract pytest` и системный Tesseract; `pywin32`/Interception на Linux не устанавливаются. Офлайн-тесты не нажимают кнопки в настоящем Roblox и не заменяют испытание в Windows.

Автоматизация может нарушать правила Roblox/конкретной игры. Используй только там, где она разрешена. Совместимость с драйвером, текущим интерфейсом игры и реальным обменом должна быть проверена на Windows; обход античита не реализован.
